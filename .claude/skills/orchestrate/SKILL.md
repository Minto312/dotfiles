# orchestrate — 司令塔として並列に作業する

司令塔の Claude がペインを分け、作業役の Claude を複数動かして作業を進めるときの決まり。プロジェクトだけの値 (リポジトリ、ブランチを作る元、マージの方法など) は、各プロジェクトの CLAUDE.md か notes/ に書く。ペインの操作の書き方は、末尾の「Herdr の場合」にまとめている。

## 役割

| 役 | すること |
|---|---|
| 司令塔 | ユーザーと話し、作業を切り出して作業役に渡し、結果を集め、記録する。大きな実装は自分でしない |
| 作業役 | 渡された 1 つの作業を、自分の worktree とブランチで行い、PR を出す |
| 係 (改善役など) | ユーザーが置くと言ったときだけ置く。目的はユーザーが言ったことだけにし、最初の仕事は観察と提案までにする。スクリプトや設定の変更などの成果物は、ユーザーが求めたときに作らせる |

## 始める前

- プロジェクトの値を CLAUDE.md・notes/ で確かめる: リポジトリ、ブランチを作る元、マージの方法、Issue の置き場、記録の置き場、作業役に読ませる設計書。書かれていなければユーザーに聞き、プロジェクトの CLAUDE.md か notes/ に書く
- 作業を Issue に書き起こす
  - 1 つの Issue は、作業役 1 人が 1 回で終えられる大きさにする
  - 内容、参照する設計書、完了の条件、範囲に含めないもの、前提 (先に終わっている必要がある Issue) を書く
  - 前提の関係は GitHub の依存関係 (blocked by) で表し、まとめの Issue を作って各 Issue を子 Issue にする
  - ユーザーの操作や判断が要る Issue には、それと分かるラベルを付ける
- 同時に渡す作業は、変更するファイルが重ならないものにする
- 前提の作業がまだマージされていないときは、そのブランチから作業のブランチを作り、PR の base をそのブランチにしてよい。前提がマージされたら、main (ブランチを作る元) の上に載せ直させる

## 配置

- 司令塔は左上のペインにする
- 作業役は右の列を上下に分けて並べる。1 列は 3 段までにする
- ユーザーが置くと言った係は左下のペインにする
- 新しいペインは、フォーカスを移さずに作る
- 作業役の Claude は、ユーザーが普段使っているのと同じオプションで起動する。オプションは、動いている claude の引数 (`ps -eo args | grep claude`) で確かめる

## 作業を渡す

- 新しい作業を渡す前に、作業役の Claude を終了して起動し直す (`/clear` ではなく再起動にする)
  - 理由: 最新の CLAUDE.md と記憶を読み込み直す、前の作業のシェルが残らない、作業ごとにセッションが分かれて後から追いやすい
  - 同じ作業の続き (レビューの反映、載せ直しなど) は再起動しない
- 指示文は、前の会話を前提にせずに書く。並べる順は次のとおり
  1. `intro.md` (役割の説明)
  2. 担当: Issue の番号、ブランチ名、ブランチを作る元、変更してよい範囲、完了の確かめ方、範囲に含めないもの
  3. `worker-rules.md` (共通の決まり)
- 長い指示文は一時ディレクトリにファイルで作ってから送る
- 完了は Bash の `run_in_background` で待ち、知らせを受けてから結果を読む。待つ間に別の作業役の結果を処理してよい

## ユーザーと作業役のやり取り

- ユーザーは作業役のペインで直接やり取りすることがある
- 作業役の質問には、ユーザーがそのペインで答える。司令塔は質問を中継しない
- ユーザーが使っている作業役には、指示を送らず、止めず、再起動もしない。使っているとみなすのは次のとき
  - そのペインにフォーカスがある
  - 入力欄にユーザーの入力がある
  - 作業役がユーザーの回答を待っている
- 次の作業は、作業役が待機中で、フォーカスが外れてから渡す
- 入力欄に薄い文字で出る文は、Claude Code が出す入力の候補で、ユーザーの入力ではない。ユーザーの決定として扱わない

## 結果を集める

- 作業役の報告は画面から読む。画面から消えた部分は読めないので、報告の全文は PR の本文から読む
- 作業役が見つけた不足や決めごとは、新しい Issue か既存の Issue へのコメントにする
- PR の本文に「Closes #<番号>」がなく Issue と結び付いていなければ、司令塔が足す

## マージ

- マージの許可は司令塔が受ける。司令塔は次の順に進める
  1. プロジェクトのマージの方法でマージする。コミットメッセージに AI の署名がないことを確かめる
  2. ブランチ (手元とリモート) と worktree を消す。消す前に、未コミットのファイルがないことを確かめる
  3. そのマージを待っている作業役に、続き (載せ直しなど) を指示する
- PR を作った作業役がそのセッションのまま待っているときは、ユーザーがそのペインで直接マージを頼んでもよい。その場合も、司令塔は PR の状態を見て、後に続く作業を進める

## 記録

- プロジェクトの記録 (notes/、CLAUDE.md の現況) は司令塔だけが書く。作業役どうしの書き込みがぶつからないようにするため
- 決まったこと、分かったこと、作業役への割り当ては、その都度記録する

## Herdr の場合

コマンドの詳しい使い方は `herdr` スキルを読む。ここには、この手順で使うものだけを書く。ほかの端末多重化ツールに移ったら、この節を差し替える。

```bash
# 分割する。新しいペインの ID は .result.pane.pane_id
herdr pane split --current --direction right --cwd "$PWD" --no-focus
herdr pane split --pane <ペイン ID> --direction down --cwd "$PWD" --no-focus

# 作業役を起動する。名前は [a-z][a-z0-9_-]* で一意にする
herdr agent start <名前> --kind claude --pane <ペイン ID> --timeout 60000 -- <普段のオプション>

# 指示を送る
herdr agent prompt <名前> "$(cat <指示文のファイル>)"

# 待つ。idle・done・blocked で返る (blocked はユーザーへの質問の画面で止まっている)
herdr agent wait <名前> --timeout <ミリ秒>

# 読む
herdr agent read <名前> --source visible

# 再起動する。作業中なら先に esc で止める。/exit でペインはシェルに戻る
herdr agent send-keys <名前> esc
herdr agent prompt <名前> "/exit"
herdr agent start <名前> --kind claude --pane <ペイン ID> --timeout 60000 -- <普段のオプション>

# ユーザーが使っているかを確かめる
herdr agent get <名前>      # focused が true なら、ユーザーがそのペインを見ている
herdr agent read <名前> --source visible --format ansi | grep -a '❯'   # 文に ESC[2m が付いていれば入力の候補
```

- Claude Code は端末の代替画面を使うので、`--lines` を増やしても、画面から消えた返答は読めない
