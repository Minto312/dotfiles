## 報告 (インテリジェンス)

調査・分析の結果を私に示す文書 (artifact・Markdown・Docs・チャットでのまとまった報告) は，集めた情報を並べたものではなく，私の判断に使えるインテリジェンスとして書いてください．次の 4A を満たしてください．

- **Accurate (正確である)**
  - 事実・前提・判断を分けて書く
  - 判断には可能性の程度と確信度 (高・中・低) を付ける．可能性の程度は次の語と範囲で書く: ほぼない (1〜5%)・非常に低い (5〜20%)・低い (20〜45%)・五分五分 (45〜55%)・高い (55〜80%)・非常に高い (80〜95%)・ほぼ確実 (95〜99%)．「〜の可能性がある」だけで終えない
  - 事実には出典を付ける．情報源の信頼性と，情報そのものの確からしさを分けて評価する．自分で確かめていないことは，確かめていないと書く
  - 最も有力な仮説のほかに検討した仮説と，それを退けた理由を書く
  - 私の希望や，先に出した結論に合わせて判断を変えない
- **Audience Focused (私に向けて書く)**
  - 私が何を決めるための文書かを，書く前に確かめる．問いが分からなければ，書く前に聞く
  - 私の状況 (会社・案件・環境) に当てはめて書く．一般論で終えない
  - 私が既に知っていることや，判断に使わない情報は書かない
- **Actionable (行動につながる)**
  - 結論を冒頭に書く (BLUF)
  - 判断ごとに，私にとって何を意味するか，私が何をすべきか・何を決められるかを書く
  - 判断が正しいかを後で確かめるための兆候と，分からなかったこと・追加で調べるべきことを書く
- **Adequate Timing (時機に合う)**
  - 判断の期限に間に合わせることを，完全さより優先する．期限が分からないときは聞く
  - 調べ終わっていない状態で出すときは，足りない部分と，それによる不確かさを書く
  - 前の報告から判断が変わったときは，変わった理由を書く

構成の基本は「1. 結論 → 2. 主要な判断 (可能性・確信度付き) → 3. 根拠と出典 → 4. 前提 → 5. 検討した他の仮説 → 6. 私への影響と次の行動 → 7. 注視する兆候 → 8. 分からなかったこと」です．短い問いには短く答えてよく，全項目を毎回埋める必要はありません．ただし結論・確からしさ・次の行動は省かないでください．

## コマンドの実行の依頼

私にコマンドを実行してもらうとき (`bw unlock` など) は，`! <コマンド>` を案内するのではなく，tmux のペインを作り，コマンドを入力した状態にしてから頼んでください．
- 自分のペインの下に，フォーカスを移さずに作る (`tmux split-window -d -v -l 12 -t "$TMUX_PANE" -c <ディレクトリ> -P -F '#{pane_id}'`)
- ペインの `@agent_name` を `cmd` にし，`tmux send-keys -l` でコマンドだけを送る．Enter は送らない
- 頼むときは，そのペインの番号を伝える．ペインを足すと番号が振り直されるので，ほかのペインの新しい番号も伝える
- 使い終わったら，閉じてよいかを聞く
- tmux の外 (`$TMUX` が無い) で動いているときは，`! <コマンド>` を案内する

## 開発ワークフロー
はじめに，`git pull`を行いブランチを最新の状態にしてください．

ファイルに変更を加える際には，.claude/ 以下にworktree を切って作業を行い，常に並列に作業できるようにしてください．

ペインを分けて作業役の Claude を動かす (リーダーとして並列に作業する) ときは，どのワークスペースでも始める前に `orchestrate` スキルを読んでください．

Claude-Session: https://claude.ai/code/session_…
https://claude.ai/code/session_…        ← 裸の URL のみの行も対象
